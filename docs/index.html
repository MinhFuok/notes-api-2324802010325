Dự án minh họa môi trường phát triển trên đám mây bằng GitHub Codespaces, Node.js, Express và GitHub Pages.

API Hello Cloud cung cấp dữ liệu JSON qua HTTP, bao gồm thông tin máy chủ, CPU, RAM, hệ điều hành và thời gian hoạt động.

5 đặc tính điện toán đám mây theo NIST

1. On-demand self-service

Tự tạo và khởi chạy GitHub Codespace mà không cần nhân viên nhà cung cấp hỗ trợ.

Thực tế: Sinh viên tự cấp phát môi trường lập trình qua GitHub.

2. Broad network access

Tài nguyên Cloud có thể truy cập qua mạng bằng nhiều loại thiết bị.

Thực tế: Truy cập Hello Cloud API bằng điện thoại thông qua URL Public của Codespaces.

3. Resource pooling

Tài nguyên được cấp phát từ hạ tầng Cloud dùng chung của nhà cung cấp.

Thực tế: Sử dụng môi trường Codespaces với 2 CPU và 7.8 GB RAM theo API.

4. Rapid elasticity

Tài nguyên Cloud có khả năng mở rộng hoặc thu hẹp theo nhu cầu.

Thực tế: Codespaces hỗ trợ thay đổi cấu hình máy. Đã thực hiện khởi chạy và dừng Codespace, chưa kiểm thử co giãn tự động.

5. Measured service

Mức sử dụng tài nguyên được theo dõi, đo lường và thống kê.

Thực tế: GitHub Billing Usage ghi nhận 0.49 GB-month lưu trữ, chi phí trước ưu đãi $0.03, số tiền thực trả $0.

Lab 02 - Ảo hóa, Container và CloudSim Plus

Đóng gói API Hello Cloud bằng Docker, chạy hai container, giới hạn tài nguyên, phát hành image lên GHCR và mô phỏng trung tâm dữ liệu bằng CloudSim Plus.

2. Bảng 1 - So sánh máy ảo và Container

Tiêu chí Codespace (VM) Container notes2
Thời gian khởi động 190 giây (thời gian tạo Codespace, Lab 01) 0,409 giây (chạy tiến trình Node.js ngắn)
Kích thước 15 GB-tháng (hạn mức lưu trữ miễn phí) 251 MB Disk Usage; 63,3 MB Content Size
Nhân hệ điều hành Kernel Linux của máy ảo Codespaces Dùng chung kernel 6.8.0-1070-azure với Docker host
Mức cô lập Cô lập bằng công nghệ máy ảo Namespaces và cgroups; giới hạn 0,5 CPU, 128 MiB RAM

Thời gian tạo Codespace và chạy tiến trình Node.js trong container không phải hai phép đo tương đương. Hạn mức 15 GB-tháng không phải kích thước thực tế của VM.

Nhận xét: Container khởi chạy tiến trình thử nghiệm nhanh, chia sẻ Linux kernel với Docker host và sử dụng cgroups để giới hạn tài nguyên. Máy ảo có lớp cô lập độc lập hơn.

3. Bảng 2 - Kết quả mô phỏng CloudSim Plus

Lần Thay đổi Finish Time lớn nhất (giây)
0 Cấu hình mặc định 20,0
1 Nhân đôi VMS: 2 → 4 45,6
2 Nhân đôi CLOUDLETS: 4 → 8 40,1*
3 Đổi sang CloudletSchedulerSpaceShared 20,1

* Lần 2 cấu hình 8 Cloudlet nhưng bảng kết quả chỉ xác nhận 4 Cloudlet SUCCESS. Giá trị 40,1 giây là thời điểm hoàn thành lớn nhất của 4 Cloudlet đã hoàn thành, không phải của toàn bộ 8 Cloudlet. Mô phỏng có cảnh báo VM bị hủy khi còn tác vụ.

Nhận xét: Lần 0 và lần 3 có thời gian hoàn thành gần nhau (20,0 và 20,1 giây). Lần 1 có thời gian hoàn thành lớn nhất là 45,6 giây. Lần 2 chưa hoàn thành toàn bộ Cloudlet nên chưa thể so sánh trực tiếp với các lần còn lại.
